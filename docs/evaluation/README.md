Основной риск — круговая проверка: агент сам выводит требования, пишет код и пишет тесты к собственному пониманию. Независимые acceptance cases должны происходить из утверждённого смысла, с согласованным входом/выходом, прежде чем тот же агент пишет реализацию. Часть кейсов скрыта от генератора до оценки, затем сохраняется как реплицируемое доказательство.

Результат отдельного кейса: NOT_RUN, PASS, FAIL, BLOCKED или INCONCLUSIVE. Наличие тестового файла не является результатом тестирования.
