# Независимые тестовые оракулы — план

Статус: **PROPOSED**, не target acceptance и не исполняемые тесты. Основа: [historical SCN-006](../research/legacy-checker.md). Утвердить предметную область в P2 **до** генерации.

| ID | Кейс | Ожидаемое наблюдаемое поведение |
| --- | --- | --- |
| O-01 | Одна covering Permit | Правило с ID, действием, порядком и происхождением |
| O-02 | Несколько covering Permit/Deny | **Все** совпадения в исходном policy order |
| O-03 | Релевантное место, нет covering rule | Явный no-match, не универсальный deny |
| O-04 | Источник/снимок недоступен | UNKNOWN/incomplete, не пустой результат с утверждением об отсутствии политики |
| O-05 | Наличие разновременных источников | Видны provenance/freshness; историческое не выдано за live |
| O-06 | Несколько мест применения, разные результаты | Отдельные результаты, без выдуманного общей allow/deny |
| O-07 | Неверный IPv4, protocol, port | Явный отказ на неверном входе |
| O-08 | CIDR/range/port boundaries | Нет расширения или сужения predicate |
| O-09 | Запрещённая device mutation | Никаких изменений, команд или реальных poll устройств |

Вопросы до P2: что входит в поддерживаемую ACL семантику? каковы роли source port/ICMP, NAT, порядок в вендорах, статус snapshot freshness и отрицательные/неполные данные? Что считать релевантной attachment в первой fixture-based версии? Ответы требуют принятого решения, а не автоматических догадок.

Каждый утверждённый oracle сохранит requirement ID, tuple/fixtures, expected results, дату/автора принятия, источник и SHA. Критические negative cases не подгонять под реализацию.
