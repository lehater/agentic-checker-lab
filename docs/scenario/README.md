# Checker — задача владельца

**Исходная постановка:** [owner-problem-brief.md](owner-problem-brief.md).

Это входная предметная потребность, а не принятые Harness requirements или выбранный дизайн. Инженерная детализация, выбор применимых Authorities/Capabilities, вопросы к владельцу и принятие артефактов должны происходить через актуальный Harness Consumer Pack. Предыдущих CURRENT/semantic admission для Checker в текущем состоянии проекта нет.

Исторические Product/SSSR материалы могут служить свидетельствами, но не подменяют новую постановку. Для начального прототипа допустимы синтетические данные и заглушки внешних зависимостей; не подключаться к реальным устройствам.
