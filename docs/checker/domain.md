# Domain Use Case — исследовать сохранённые ACL

Основание: [требования](../../.harness/knowledge/requirements.yaml),
REQ-CHECKER-101..104. Владение: DOMAIN-USE-CASE-DESIGN. Потребители: интерфейс,
verification и реализация Checker. Отдельный контракт нужен для проверяемой
семантики matching; стратегическая классификация инвестиций здесь не нужна.

Инициатор — оператор. Предусловие: один конкретный поток и предоставленные
источником релевантности пары устройство/ACL со снимками и местами применения.
В первой версии разработчик выбирает IPv4, TCP/UDP и порты 0..65535; оба порта
обязательны. Это явное ограничение прототипа в рамках порученного минимального
набора, а не утверждение об исторической сети или всех ACL.

Минимальные поддерживаемые правила: точный IPv4 адрес или CIDR сеть в каждом
адресном поле; TCP, UDP либо any в поле протокола; замкнутый диапазон портов
для каждого портового поля (один порт — диапазон с равными концами, any —
0..65535). Сеть содержит адрес по общему префиксу, включая крайние адреса:
это сопоставление адресов, а не выделение пригодных адресов хостов подсети.
Маски vendor wildcard, отрицания, группы, NAT и дополнительные предикаты
не поддерживаются и не аппроксимируются.

Правило подходит тогда и только тогда, когда одновременно: source входит в
source сеть, destination входит в destination сеть, protocol совпадает либо
правило any, оба порта находятся в соответствующих включительных диапазонах.
Action не участвует в этом предикате. Все совпавшие permit/deny правила
сохраняются в порядке списка снимка, без остановки на первом совпадении,
сортировки по ID или приоритета action. Контекст правила определяется парой
устройство/ACL. Места применения относятся к ACL и не создают копии правила.
Повторно возвращённая та же пара источником релевантности обрабатывается один раз.

При полном предоставленном снимке с нулём совпадений результат — NO_MATCH,
при совпадениях — MATCHES. Пустой корректный список правил — NO_MATCH.
Отсутствующий снимок, неверные входные значения, неподдерживаемые/некорректные
предикаты не означают NO_MATCH: запрос отклоняется с явной диагностикой,
без выдачи успешного полного отчёта. Такой отказ — консервативная граница
поддержанного набора; частичный результат не заявлен исходной постановкой.
Релевантность предоставляется имитацией, не объявляется реальным путём.

Постусловие: для каждой уникальной релевантной пары показаны сведения ACL и
мест применения, все подходящие правила с сохранёнными полями и action либо
явное отсутствие совпадений. Нерелевантные снимки не рассматриваются.
Состояние сети/снимков не меняется. Общего verdict и синтетического implicit deny нет.

Новых предметных вопросов для этого ограниченного синтетического контракта нет.
Изменение поддерживаемых предикатов, partial results, freshness policy или live
источников требует пересмотра доменного контракта и проверок до реализации.
