## Exact published question

### Q-009

Если поиск по корректным данным не обнаружил ни одного потенциально релевантного межсетевого экрана (например, на всех проверенных FW оба адреса соответствуют одному интерфейсу), какой смысл и какой результат должен увидеть оператор? Нужно ли явно отличать этот случай от найденного FW без ACL и от ACL без совпавших правил?

Why: Q-002 establishes route-based FW relevance; Q-004/D-007 distinguishes relevant FW with no ACL from relevant ACL with zero matches, but neither specifies the result when **no FW at all** is relevant. CR-01 classified this new question OWNER_DECISION; Q-002/Q-004 are dependencies already answered.

## Owner answer and approved normalization

Owner's response (substantive excerpt, 2026-10-29): «все экраны, которые релевантные, мы просто формируем список»; «под каждым ... экраном ... все релевантные списки доступа и точки их крепления»; «в каждом ... access листы мы показываем релевантные правила»; explicitly separated **what is shown** from **how it is shown**. Relevant objects at each level remain present even when they have zero children. The owner presented this as hierarchical facts, not a prescribed UX design.

Approved normalized answer: Результат Checker содержит три уровня фактов: (1) все релевантные FW независимо от наличия ACL; (2) внутри каждого FW все релевантные ACL со всеми их релевантными точками применения независимо от наличия совпавших правил; (3) внутри каждого ACL только совпавшие по принятым критериям правила. Если нет релевантных FW, множество FW пусто; если у релевантного FW нет релевантных ACL, сохраняется сам FW с пустым набором ACL; если у релевантного ACL нет совпавших правил, сохраняется ACL с пустым набором совпадений. Это описание состава и вложенности фактов, а не формы UI или обязательных специальных кодов статусов. Отсутствие успешно полученного снимка не приравнивается к доказанному отсутствию совпадений.

Critical review boundary: a named ACL with no matching rules is a valid empty rule set (D-007). A named ACL lacking **any first successful snapshot** has no valid matching evidence and remains an unapproved engineering case, not an asserted empty match set.

Example Mapping rule: Каждый релевантный FW и каждый релевантный ACL присутствуют в результате независимо от наличия дочерних сущностей; правила показываются только при совпадении.

Example: FW-A релевантен, ACL нет → FW-A с пустым набором ACL. FW-B релевантен, ACL WEB_IN есть, совпавших правил нет → FW-B/WEB_IN с пустым набором правил. Никаких релевантных FW → пустой набор FW.

Counterexample: Не показывать релевантный FW лишь потому, что у него нет ACL, либо скрыть релевантный именованный ACL из-за отсутствия совпавших правил, либо выдать обязательные статусы/вердикт вместо фактов.
