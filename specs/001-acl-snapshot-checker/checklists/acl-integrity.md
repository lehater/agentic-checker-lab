# ACL Integrity Requirements Checklist

**Purpose:** Проверить качество требований и интерфейсов Checker перед передачей RPG.
**Created:** 2026-10-16
**Feature:** [spec.md](../spec.md)
**Review ownership:** independent reviewer; this checklist is **not yet reviewed**, so every item unchecked.

## Requirement Completeness
- [ ] CHK001 Для каждого из пяти полей потока определены допустимые значения и невалидные случаи?
- [ ] CHK002 Для каждого релевантного ACL явно определена реакция на отсутствующий snapshot?
- [ ] CHK003 Однозначно определён случай нескольких ACL на одном устройстве?
- [ ] CHK004 Сведения о placements ограничены метаданными, а не используют их для выдумывания транзитного пути?

## Requirement Clarity
- [ ] CHK005 Явно ли указано, как `any`/CIDR/интервалы портов соотносятся с пятью полями запроса?
- [ ] CHK006 Явно ли определено, включаются ли границы диапазонов портов?
- [ ] CHK007 Однозначно ли установлен источник порядка правил — массив snapshot, а не номер rule ID?
- [ ] CHK008 Отличимы ли отсутствие подходящих правил и неполные данные?

## Consistency / Forbidden Inferences
- [ ] CHK009 Совместимы ли описание «показать все» и отсутствие early stop по `deny`/`permit`?
- [ ] CHK010 Ни один интерфейс/отчёт не обещает глобальный permit/deny verdict?
- [ ] CHK011 Технический план не утверждает, что релевантность равна реальному пути?
- [ ] CHK012 План не включает реальные firewall, vendor-specific parsing, routing algorithm или production DB?

## Measurability and Scenario Coverage
- [ ] CHK013 Есть ли сценарий с двумя совпадающими правилами, имеющими противоположные действия?
- [ ] CHK014 Есть ли сценарии пустой релевантности, пустого ACL и отсутствия совпадений?
- [ ] CHK015 Есть ли независимые проверки включительности диапазонов и CIDR boundary?
- [ ] CHK016 Есть ли проверка ошибки неизвестного ACL-предиката без молчаливой подмены?
- [ ] CHK017 Можно ли проверить, что полученный JSON относится к фиксированной версии контракта?

## Assumptions / Traceability
- [ ] CHK018 Отмечены ли решения, не содержащиеся в исходном owner brief, как допущения/проектные решения?
- [ ] CHK019 Есть ли связь каждого обязательного FR с конкретным acceptance scenario или будущим тестовым обязательством?
- [ ] CHK020 Будет ли RPG-план проверяться на сохранение ограничений CLI, five-tuple и порядка?

## Notes
Пункты проверяют **тексты требований**, а не работоспособность реализации. Отметки проставляет независимый рецензент. Автор не имеет оснований помечать их выполненными автоматически.
